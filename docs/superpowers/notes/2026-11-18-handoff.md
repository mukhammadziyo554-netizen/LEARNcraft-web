# Front-end redesign: notes for the team

Branch `fix/frontend-polish`, draft PR #1. Spec and plan are next to this file in `docs/superpowers/`.

## Decisions already made

- **Sign-in required on Settings, Community, Practice and the civil foundations study page** (owner, 2026-11-18). Implemented with `js/require-login.js`, which uses the same sign-in record as the rest of the site (`localStorage.learncraft_current_user`, written by `pages/login.html`).
  - The old pages imported `requireAuth` from `js/auth.js` (Firebase) by a wrong path, so it never ran. It was **not** used, because nobody signs in to Firebase: `pages/login.html` only writes localStorage. Using it would have redirected every visitor, signed in or not.

## Needs a decision or backend work

1. **Two sign-in systems.** `js/auth.js` (Firebase) exists, but the login page uses localStorage only and stores passwords in plain text in `learncraft_users`. Anyone can read them in the browser, and anyone can "sign in" by editing localStorage. The sign-in gate is a convenience, not security. Pick one system (Firebase looks intended) and move login, sign-up and the gate to it.
2. **Admin pages have no protection of their own.** `admin/admin-dashboard.html` and `pages/ai-usage.html` (an admin analytics page) open for anyone with the URL. Hiding the Admin link (now shown only to the admin email) does not protect them.
3. **Pro plan buttons** ("Start monthly plan" etc.) used to link to `#`. There is no checkout page, so they now go to the sign-in page. Point them at real checkout when it exists.
4. **Social links** in the old footer pointed at bare homepages (`https://instagram.com`, `x.com`, `tiktok.com`, `linkedin.com`, `youtube.com`). Removed. Send the real account URLs to put them back.
5. **Ask AI is keyword-based.** Both the home chat and `pages/ask-ai.html` pick prewritten answers by keyword; neither calls an AI model. The page copy says "AI tutor". Decide whether to connect a real model or change the wording.
6. **"Track your progress" claim.** Stage progress is now saved in the browser (per device). Nothing is saved to an account, so it does not follow a user between devices.

## How to check the site

- `npm run dev` serves it on http://localhost:8000.
- `npm run check` opens every learner page on phone and desktop (plus light mode, 320px and Russian) and fails on script errors, sideways scroll, CSS shown as text, missing alt text, blocked zoom, missing landmarks, unnamed controls, emoji icons and low contrast.
- `npm run check:self` proves those checks catch real problems.
- `npm run lint` runs html-validate and stylelint.
